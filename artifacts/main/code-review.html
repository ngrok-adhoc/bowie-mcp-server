Bowie initial code review

Keep Bowie's upstream private before using the OAuth provider. The review also found two issues when switching to or recreating the Compose deployment.

The review covered staged, unstaged, and untracked files for the single-process MCP server, Holland Park catalog, and optional OAuth deployment.

Findings

P1 · Keep the OAuth upstream private

The README describes pointing the OAuth provider at a public ngrok URL for Bowie. The server checks allowed hostnames and has no built-in authentication. A publicly reachable upstream needs its own access controls to protect the catalog's add and review tools.

Document loopback or private networking as the default and require separate access controls for a public upstream.

README.md, line 31 · mcp_server.py, line 408

P2 · Persist the OAuth provider's state

The OAuth container mounts the consent icon. Recreating that container loses the signing keys, client registrations, and grants the provider stores in its writable layer. Existing clients can lose access even when the public URL stays the same.

Mount a named volume at /app/.mcp-oauth-provider.

docker-compose.yaml, line 36

P2 · Use a Compose-specific upstream setting

Reusing the documented local .env passes http://127.0.0.1:3001/mcp verbatim to the OAuth container, where loopback points at the provider itself. Compose configuration rendering confirmed the resolved URL.

Give Compose its own override or document clearing the local setting so Compose uses http://bowie:3001/mcp.

docker-compose.yaml, line 32 · README.md, line 55

P3 · Correct the Docker report's entry point

The report's startup command names server.py, which the image does not contain. Use mcp_server.py so the documented command can be reproduced.
